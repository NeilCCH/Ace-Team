# 銷售 AI 教練

保險經紀公司的銷售／增員／輔導情境教練。輸入個案後，可取得分析與話術建議，並與 AI 角色扮演，結束時取得講評。可安裝為 PWA（加到手機主畫面）。

## 三條線、九個模組

| 線 | 模組 | 範圍 |
| --- | --- | --- |
| 銷售 S | 主顧開拓 與 電話約訪 | S1–S2 名單、定聯與約訪 |
| 銷售 S | 需求分析・找痛點 | S3–S4 初步面談、發掘與深化需求 |
| 銷售 S | 說明建議書 | S5 建議書呈現、年期與額度 |
| 銷售 S | 成交與轉介 | S6 反對問題、成交與轉介 |
| 增員 R | 取得準增名單 與 接觸準增 | R1–R2 名單來源、工作溫度計 25 題 |
| 增員 R | 一次面談・發掘需求 | R3 判斷推力 |
| 增員 R | 二次面談・說明事業 | R4 創造拉力 |
| 增員 R | 決定聘用 與 新人報聘 | R5–R6 380 話術／20分鐘OPP、報聘流程 |
| 輔導 M | 輔導十字線 | 判斷團隊夥伴所在象限，給出對應輔導方式 |

每個模組的教練規則、方法論與範例個案位於 `content/modules/<模組 ID>/`。模組登錄在 `lib/modules.ts`，同一條線內的教練能看到彼此的框架卡（不跨線），診斷與評分仍只依自己模組的框架卡為準。

## 使用流程

1. 選擇模組，輸入客戶背景、進度、關鍵句與練習目標，或載入範例，再點選「開始個案分析」。
2. 依教練建議追問；需要練習時點選「開始角色扮演」。
3. 點選「結束對練並取得講評」以取得回饋。

輸入框支援多行。按 Enter 換行，按 ⌘/Ctrl + Enter 送出。教練回覆可複製；失敗時可重試。

## 資料處理與法遵

個案內容會即時送至第三方 AI 服務 Anthropic 進行分析。若有設定 `DATABASE_URL`，每個個案與對話會存進 Postgres，用來產生儀表板（累積個案數、完成率、模組練習次數、最近個案）；沒設定 `DATABASE_URL` 時，教練陪練功能照常可用，只是不留紀錄、儀表板會顯示讀取失敗。請勿將 AI 建議視為公司核准話術、商品建議或法遵審核結果。

## 儀表板與個案記錄

儀表板（側邊欄「儀表板」）顯示累積個案數、完成個案數與完成率、平均分數、待跟進個案、各模組練習次數、最近個案列表。資料表結構在 `db/schema.sql`——首次啟用時，到 Postgres 的 SQL Editor（例如 Neon 後台）貼上整段執行一次建表即可，之後重複執行也安全（`CREATE TABLE IF NOT EXISTS`）。

分數是從教練角色扮演講評的文字裡抓「數字+分」取平均，是盡力而為的擷取，不是結構化評分協議，抓不到分數時個案一樣會標記完成、只是分數留空。

## 登入與存取控制

整個網站（含所有頁面與 API）都需要先登入才能使用，未登入會被導到 `/login`；`/apply`（申請帳號）是唯一公開、不用登入就能進的頁面。**每個人都有自己的密碼**，不再是大家共用一組存取碼。環境變數：

- `ALLOWED_EMAILS`：**管理員**名單，逗號分隔，不分大小寫。這些帳號永遠可以登入、不受下面的申請／開通流程限制，也是唯一能進 `/admin` 開通別人帳號、重設別人密碼的人
- `ACCESS_CODE`：只給**管理員第一次登入**當密碼用的開通碼（bootstrap）。管理員登入後到側邊欄「更改密碼」設定自己的個人密碼之後，之後就都用自己的密碼登入，`ACCESS_CODE` 在那之後就用不到了（除非又有新的管理員帳號、還沒設過個人密碼）
- `SESSION_SECRET`：用來簽登入 session 的密鑰，自己打一串夠長的隨機字串即可

**一般使用者的帳號流程**：
1. 到 `/apply` 填 email、**自己設一組密碼**、並設定一個**安全問題與答案**（姓名、備註選填），送出後狀態是「待審核」，存進 `users` 資料表（需要資料庫，見下方）
2. 管理員登入後，側邊欄會多一個「帳號審核後台」連到 `/admin`，列出所有申請，點「開通」或「拒絕」
3. 開通後，使用者回 `/login` 用申請時的 email + 自己設定的密碼即可登入，之後也能自己到「更改密碼」換密碼，或補設定／更新安全問題

密碼與安全問題答案都用 Node 內建的 `scrypt`（加鹽雜湊）存放，資料庫裡看不到明碼；答案比對時忽略大小寫與前後空白。

**忘記密碼**：登入頁有「忘記密碼？」連到 `/forgot-password`，輸入 email → 系統顯示當初設定的安全問題 → 答對 + 設定新密碼即可自助重設，不需要管理員介入。管理員（`ALLOWED_EMAILS`）因為不走 `/apply`，預設沒有安全問題，要先登入後到「更改密碼」頁補設定一組，才能使用這個自助流程；沒設定安全問題的帳號忘記密碼時，就只能請管理員到 `/admin` 按「重設密碼」給一組暫用密碼，再自己用LINE等管道私下告知對方。

**已知限制**：登入 session 是簽章過的 cookie，一旦核發，30 天內都有效，開通／撤銷狀態只在「登入當下」檢查一次，不會讓已登入的人被即時踢出——對內部小團隊工具來說是合理的取捨，之後真的需要即時撤銷再評估加上伺服器端 session 查核。

## 本機執行

```bash
npm ci
cp .env.example .env.local
npm run dev
```

在 `.env.local` 設定 `ANTHROPIC_API_KEY`、`ALLOWED_EMAILS`、`ACCESS_CODE`、`SESSION_SECRET`（`DATABASE_URL` 選填），然後開啟 http://localhost:3000（會先導到登入頁）。可用 `ANTHROPIC_MODEL` 指定模型。執行 `npm run lint` 做 TypeScript 靜態檢查，執行 `npm run build` 確認建置。

## 部署

可將 GitHub repo 連接 Vercel，並在部署環境設定 `ANTHROPIC_API_KEY`、`ALLOWED_EMAILS`、`ACCESS_CODE`、`SESSION_SECRET`（要用儀表板的話再加資料庫連線字串，見下方）。不要把這些值提交到 Git。

**透過 Vercel 的 Neon 整合連接資料庫時**：程式碼會依序找 `DATABASE_URL`、`POSTGRES_URL` 這兩個環境變數，用找到的第一個。Neon 整合實際建立的變數名稱依當初設定的 custom prefix 而定——不一定是 `DATABASE_URL`，連完後務必到 Vercel 專案的 **Settings → Environments → Production** 裡確認真正的變數名稱（例如 `POSTGRES_URL`），並且 **新增/修改環境變數後要重新部署（Deployments → 最新那筆 → Redeploy）才會生效**，光是在設定頁存檔不會讓已經部署的函式讀到新變數。

正式上線前請確認 Anthropic Console 帳號已經完成付費設定（不是免費評估額度），否則 API 呼叫會失敗或被擋。
